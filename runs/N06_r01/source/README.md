# N06_r01 — Survey transformer with question and answer embeddings

This submission tests whether survey wording helps the shared transformer that produced N01. A respondent representation predicts each question through both an independent head and a learned component shared by answers with similar wording. The scientific comparison is N06 versus N01 on each survey, with F05 as the statistical reference.

## Prepare the wording features once

1. Read the three official public metadata dictionaries and the configured gate sentinel. Include every `PREDICT` question and its declared answer levels, appending the sentinel last for gated questions. UNICEF contributes 12 questions and 61 options, World Bank 76 and 655, and UNHCR 213 and 834. All 301 questions have published wording.
2. Encode two strings for each option. The first contains the original answer label. The second places that answer alongside its complete question. For the gate sentinel, use “Not asked because of survey routing”. Genuine nonresponse labels retain their supplied wording. Numeric codes and labels are kept as published. The English sentence encoder may represent opaque codes poorly, so every option also has an independently trained head.
3. Use the frozen public `sentence-transformers/all-MiniLM-L6-v2` encoder at revision `c9745ed1d9f207416be6d2e6f8de32d1f16199bf`. Mean-pool the nonpadding token states and normalize each 384-dimensional sentence embedding. The longest question–answer string uses 66 tokens of the 256-token limit. The encoder ran on the preparation machine using only the public wording. [Encoder model card and Apache-2.0 license declaration](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2/blob/c9745ed1d9f207416be6d2e6f8de32d1f16199bf/README.md)
4. Within each question, subtract the mean option vector from each embedding. Fit separate 32-component PCA projections to these public option and question–option differences using all three dictionaries. Normalize the typical magnitude within each question, give both channels equal weight, and save the 64 numbers per option. Centering retains the distinctions between legal options that can change their softmax probabilities. The contextual channel can distinguish identically labelled answers to different questions.
5. Save the half-precision vectors and stable lookup keys in `semantic_vectors.npz`. The asset has 1,550 rows, occupies 212,679 bytes, and has SHA-256 `a6a973cc91ae131f5e6fb2a7673cbde8c91f3fd094b9ca019fc60a255ca0dff0`. The lookup key identifies the item, exact question, original value and gate status. The preparation inputs, hashes and derived dimensions appear in `semantic_provenance.json`. The campaign script `tools/build_semantic_vectors.py` recreates the asset from the pinned model directory and the public repository's `data/` directory. Encoder weights and tokenizer stay on the preparation machine.

## Execute the submission

1. At import, `main.py` loads the configuration and initializes `semantic_candidate.py`. The provider checks the embedded asset digest, dimensions and unique keys, then holds the vectors in memory. Runtime dependencies are the same as N01. The grader needs no model prefetch.
2. On each survey call, encode only `GIVEN` categories as respondent inputs. Use the runtime metadata to gather wording features in the actual option order. A reordered option list stays aligned. If wording or a category is unfamiliar, that question uses its independent output head. Gated and unanswered outcomes remain distinct.
3. Use N01's category embeddings, shared summary token, two width-64 transformer layers with four attention heads, normalization, and packed independent output heads. Add one shared 64-by-64 trainable projection. For respondent representation `h`, item-option vector `v`, and projection `W`, the new option logit is `independent_logit + 0.5 * (h W) · v`. The projection starts at zero so the initial logits coincide with N01's under a common seed. Differences emerge as visible labels train the shared projection. The extra 4,096 trainable parameters and resulting regularization also affect the comparison.
4. Follow N01's split and training procedure. The wrapper uses a separate whole-respondent outer split and fits on up to 3,072 comparison rows. Inside each fit, hold out up to 256 respondents for epoch selection, train for up to 16 epochs with patience three, and start fresh for the selected number of epochs on all available fitting rows. The standalone submission then repeats training on all visible respondents for its final predictions. Mask missing labels in the loss; train on visible answers across targets jointly.
5. Convert the logits for each question to probabilities on its declared support, mixing in 2% of its smoothed empirical marginal. Single-class and unseen targets use the positive marginal. Return one vector per blank cell in the official order. The cumulative 400-second neural-work budget and 825-second overall work guard bound optional work before the organizer's 900-second limit. A budget interruption returns the wrapper's marginal fallback.

In full-size validation, check that every comparison and final fit completes, that `semantic_matched_targets` equals 12/76/213 for the respective surveys, and that the fitted `semantic_projection_norm` is positive. The focused tests also check that changing wording changes the contextual channel, reordering answers preserves alignment, the gate has a distinct embedding from genuine nonresponse, and a gradient from one option can change other option logits through the shared projection. Hosted predictive quality is determined by the competition scoring result.
